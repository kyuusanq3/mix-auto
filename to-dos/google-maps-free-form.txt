## Background

The Eonon head unit this app runs on has Android freeform window mode enabled
(confirmed working). The goal is to launch Google Maps as a freeform window
pinned to exactly the map pane area of DashboardScreen, so it appears seamlessly
embedded — similar to how LecaAuto does it. The launcher (MixAuto) stays in the
foreground drawing its media pane, shortcut dock, and status strip; Google Maps
sits in the map pane bounds as a separate Android window.

The unit has Google Play Services and the stock `com.google.android.apps.maps`
install — `google.navigation:` intents are reliable. Do **not** add
`play-services-location` or any `com.google.android.gms` dependency; freeform
launch uses only standard Android APIs.

---
## How freeform launching works

Use `ActivityOptions.setLaunchBounds(Rect)` — public API when the device has
freeform mode enabled. No manifest permission required.

```kotlin
val options = ActivityOptions.makeBasic()
options.launchBounds = Rect(left, top, right, bottom)  // screen pixels
context.startActivity(intent, options.toBundle())
```

The Rect must be actual screen-pixel coordinates of the map pane, not dp.
`Modifier.onGloballyPositioned` + `boundsInWindow()` returns window coords —
correct for edge-to-edge `MainActivity` (`setDecorFitsSystemWindows(false)`).

```

       ├── DashboardStatusBar (optional top strip — map pane is below it)

       │     (portrait Column, landscape LHD Row, landscape RHD Row,
       │      vertical-dock landscape variants)
       ├── DashboardSecondaryPane (media pane — search, POI detail, settings…)
       └── ShortcutDock
             DriverSideCluster: App Drawer + Voice Search mic
             CenterDockCluster: up to 5 pinned apps
             DockMusicSideControl: 280 dp music slot
```

**There is no `SettingsDockItem` or `MapDataDockItem`.** Map settings live on
the map toolbar (`MapSettingsFab`, bottom-start). Launcher settings are in the
app drawer header gear. Model the G.Maps item on `AppDrawerDockItem` /
`VoiceSearchDockItem` / `PinnedDockAppItem` in `ShortcutDock.kt`.

**Destination flow today (do not break for MapLibre mode):**
1. Search / recent / nearby row tap → `onPreviewSearchPlace` → `POI_DETAIL`
   panel (does **not** navigate immediately).
2. User taps **Navigate** in `PoiDetailPane` → `onDestinationSelected` (recent)
   + `mapEngine.navigateToCoordinates()` in `DashboardSecondaryPane`.
3. MapLibre then may show route picker (`ROUTE_PICKER`) or dive into nav.

**Google Maps mode must intercept step 2** (and only when `googleMapsMode` is
ON). Do not change search preview / POI detail UX.

**Overlay split lock:** when `ActivePanel` is SEARCH, ADD_PLACE, POI_DETAIL,
MAP_DATA, or ROUTE_PICKER, map pane uses `OVERLAY_MAP_MEDIA_RATIO` (0.4f).
Bounds reporter must sit on the **map pane slot** (the weighted region), not the
full screen — Google Maps should only cover the map column/row, not the media
pane.

### 2. `FreeformMapManager` — NEW file

`app/src/main/java/com/kyuusanq3/mixauto/data/map/FreeformMapManager.kt`

Object or small class with:

- `GOOGLE_MAPS_PACKAGE = "com.google.android.apps.maps"`
- `launchGoogleMaps(context, boundsRect, destinationUri?)`
  - `destinationUri` non-null → `Intent(Intent.ACTION_VIEW, Uri.parse(uri))`
    e.g. `google.navigation:q=lat,lng&mode=d`
  - else → `packageManager.getLaunchIntentForPackage(GOOGLE_MAPS_PACKAGE)`
    or `ACTION_MAIN` + `setPackage`
  - `ActivityOptions.makeBasic().apply { launchBounds = boundsRect }`
  - Flags: `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_MULTIPLE_TASK`
  - Return success/failure for Toast on missing app
- `dismissGoogleMaps(context)`
  - Re-focus MixAuto: `startActivity` launcher intent with
    `FLAG_ACTIVITY_REORDER_TO_FRONT | FLAG_ACTIVITY_SINGLE_TOP`
  - Do **not** use deprecated `getRunningTasks()` on API 29+ — no reliable way
    to move Maps task to back without a Maps activity reference; bringing Mix
    Auto forward is sufficient for v1
- `isGoogleMapsInstalled(pm)` → `canLaunchApp(pm, GOOGLE_MAPS_PACKAGE)` reuse
  from `ui/components/AppIconUtils.kt`
- `isFreeformSupported(pm)` →
  `pm.hasSystemFeature(PackageManager.FEATURE_FREEFORM_WINDOW_MANAGEMENT)` on
  API 26+; return **true** as fallback on this Eonon unit
- `boundsChangedEnough(a, b, thresholdPx = 10)` helper for relaunch debounce
- Store `lastLaunchBounds` internally to avoid relaunch spam

### 4. Map pane bounds + placeholder — `DashboardScreen.kt`

**Do not** add bounds only inside `CarMapViewContainer` — there are multiple
`CarMapViewContainer` call sites across portrait/landscape/LHD/RHD branches.

Extract a shared wrapper (private composable in `DashboardScreen.kt`):

```kotlin
@Composable
private fun MapPaneSlot(
    googleMapsMode: Boolean,
    onMapBoundsChanged: (Rect) -> Unit,
    onMapEnginePause: () -> Unit,
    onMapEngineResume: () -> Unit,
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit,
)
```

- Outer `Box(modifier.onGloballyPositioned { … boundsInWindow() → onMapBoundsChanged })`
- `googleMapsMode == true` → inner `Box(Modifier.fillMaxSize().background(OledBlack))`
- `googleMapsMode == false` → `content()` (`CarMapViewContainer`)
- `LaunchedEffect(googleMapsMode)` → `onMapEnginePause()` when entering GMaps
  mode, `onMapEngineResume()` when leaving (calls `mapEngine.onPause()` /
  `onResume()` — **never** `onDestroy()`; engine lives in `MapHostViewModel`)

Replace each `CarMapViewContainer(…)` weighted modifier with
`MapPaneSlot(…) { CarMapViewContainer(…) }` — keep all existing
`CarMapViewContainer` props unchanged inside `content`.

**Bounds relaunch** in `DashboardScreen`:

```kotlin
LaunchedEffect(googleMapsMode, mapBounds, pendingDestinationUri) {
    if (!googleMapsMode || mapBounds == null) return@LaunchedEffect
    if (bounds changed > 10px OR first launch OR new destination URI) {
        FreeformMapManager.launchGoogleMaps(context, mapBounds, pendingDestinationUri)
        clear pendingDestinationUri after launch
    }
}
```

Hold `mapBounds` in `remember { mutableStateOf<Rect?>(null) }` in
`DashboardScreen` (no need to hoist to `MainActivity` unless activity-level
focus helpers require it).
